# SFD V0.7 版本检测交付与验收

日期：2026-10-02。实现为本地源码修改；本文不代表已完成 GitHub 同步、打包或游戏内多人测试。

维护前先阅读 [VERSION_CHECK_REFERENCE.md](VERSION_CHECK_REFERENCE.md)。STT 源目录可以删除，SFD 的运行与新协议验收均不引用 STT。

## 单一版本来源及状态

`SszorakFixedDirection.toc`：`## Version: V0.7`。`core/init.lua` 用 `C_AddOns.GetAddOnMetadata(addon,"Version")` 设置 `T.version`，设置页、诊断与网络回报都读取 T.version。元数据缺失时显示“未知”，不硬编码另一个发布版本。

界面：左侧“版本检测”，一个“检测版本”按钮；上方显示“本机检测基准：V0.7”，下方显示状态和可滚动的40人结果列表。列为角色名-服务器（职业色）、在线状态、实际回报版本、版本判断。长字段在行悬浮提示里显示完整原文；格式字符转义，不允许网络内容改变字体颜色或插入图标。

| 字段/状态 | 含义 |
|---|---|
| 已加载 | 本机直接读取，或来自原名单成员且严格关联本次编号/目标/截止时间的有效版本回报 |
| 与本机一致 | 完整数字版本与本机基准数值相等；尾部缺失段按0处理 |
| 需要更新 | 数字版本低于本机基准 |
| 高于本机版本 | 数字版本高于本机基准，不将本机误标成官方最新 |
| 版本格式未知 | 有有效协议回报，但版本文本不是完整数字版本；原文保留，不归为旧版 |
| 等待回报 | 5秒窗口中仍未取得当前回报 |
| 未响应 | 在线成员在本轮结束后无有效回报；安装情况未知 |
| 离线 | 当前名单显示离线；无回报时不归为未安装 |
| 已离队 | 原名单成员在窗口中离开或身份GUID改变；不接纳其之后的回报 |

已回报者随后离队，在线状态列标已离队，版本列保留本次确实收到的信息；不将其再次显示为在队。新加入或离队后重新加入者不合并进原名单，状态提示下次检测。

比较仅支持可选V/v前缀和以点分隔的完整数字段，各段不超过9位，以避免数字精度歧义。`V0.10 > V0.9`，`v0.7.0 = V0.7`。dev、V0.7-rc1、不完整数字段等标格式未知。本功能没有网络发布版本依据，不称“官方最新版”。

## SFD 协议 1

前缀：`SFDVER`（与STTVER独立）。总消息长度最多240字节。

```text
Q|1|<scanID>
R|1|<scanID>|<发起者角色-服务器>|<实际版本文本>
```

`1` 是协议号，**不是插件版本号**。插件版本V0.6等在协议有效时也能原样显示，不因版本低拒收。尚无实际历史发布版采用此协议；模拟V0.6字段测试不能证明V0.6客户端自身会回报。

检测编号：`<发起者GUID>:<服务器秒数>:<本地毫秒数>:<会话随机数>:<本轮序号>`。GUID隔离不同玩家，随机会话数和递增序号隔离重载及连续检测。最大80字节，仅允许ASCII字母数字、点、下划线、冒号、连字符。网络身份还要由事件sender核对，不把编号内容当成授权身份。

目标名和版本的转义：先百分号变`%25`，竖线变`%7C`；接收先解竖线再解百分号。拒绝无效转义和控制字符；目标原文最多120字节，版本原文最多64字节。不是数字版本不等于畸形协议，只要安全文本字段有效，就作为格式未知版本显示。

### 通道和接收校验

- 活动实例组优先：INSTANCE_CHAT；否则普通团队RAID或小队PARTY。
- 查询和回复都使用 `C_ChatInfo.SendAddonMessage` 在同一组通道发送；回复携带完整目标名，由客户端过滤，不依赖跨服私聊。
- 不调用普通聊天API，不向普通聊天发布版本查询或结果。
- 单例Frame一次注册CHAT_MSG_ADDON、PLAYER_LOGIN、GROUP_ROSTER_UPDATE、PLAYER_ENTERING_WORLD、PLAYER_LOGOUT。注册/发送按客户端枚举成功值处理；失败在检测状态显示，不静默归为未安装。

接口签名依据：[客户端生成的ChatInfo API文档源码](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ChatInfoDocumentation.lua)，其中RegisterAddonMessagePrefix与SendAddonMessage返回枚举；源码镜像只用于开发核对，不是插件运行依赖。服务器实际允许的通信能力仍须游戏内验证。
- 接收前检查前缀、长度、字段、通道、当前组完整名字/GUID；回复还必须处于本轮5秒窗口、scanID相同、目标是本机、发送者在初始快照中且未离队、GUID一致且在线。
- 初始离线但GUID不可用者仍显示在名单中；无法确认GUID时不接纳远程回报为已加载。
- 同一成员第一条有效本轮回报确定结果；重复回报不覆盖。上一轮回复、本轮超时回复、其他目标回报和非名单来源均拒绝。

### 自动回报与限流

接收端常驻；团员不需打开设置页。查询通过校验后以0.05～0.25秒延迟回报，散开团队发送时刻。每个查询者5秒门限，同一编号30秒内不重复回报；历史限流表按30秒和当前成员清理。限制按查询者分开，两个玩家同时扫描都能取得回复。延迟回调发送前再次确认发起者仍在原通道/组内且GUID相同。

扫描过程中重复点击无效；按钮禁用并显示剩余秒数。5秒独立截止计时器负责结束，0.2秒ticker仅负责倒计时，避免重复ticker浮点误差推迟截止。所有网络计时使用真实GetTime/C_Timer，不使用战术练习时钟。

检测每次保存原名单、开始本地时间/服务器时间、GUID和类别；每轮清空响应，不使用版本缓存。未组队时仅显示本机；关闭页面不终止检测，结束恢复按钮。场景切换、退出会取消扫描与延迟回复；重复打开页面不会重复注册事件。

## 历史兼容证据和不能确认的情况

完整来源与包哈希：[version_history_evidence.json](../audit/version_history_evidence.json)。审计V0.1～V0.6可取得源码、V0.4.1-p0及早期RC包，没有任何带版本的插件消息或上线广播。仅风向普通聊天发送没有版本字段。

**可识别的真实旧协议回复验收：不适用，未发现有证据的历史SFD版本协议。** 未实现猜测性兼容解析。若将来取得真实旧协议，需记录来源、字段和关联能力；无检测编号的回报必须单列“检测期间收到的旧协议回报”，历史缓存必须带“上次记录”和时间，不能冒充严格关联本轮回复。

无回报的旧版、未安装、插件未启用和通信失败都可能显示未响应。目前没有可靠手段区分这四种情况。不存在确定“未安装”状态，也不显示“低版本不支持”。

## 必须游戏内实测，尚未验证

1. 两个或更多真实账号：PARTY、RAID、INSTANCE_CHAT以及跨服同名投递，当前服务器对插件通信的限制与发送枚举。
2. 在普通副本/团队副本中脱战检测，若接口拒绝发信必须显示失败，不能认定团员没装。
3. 两位团员同时查询、真实重复包/网络延迟/掉线，5秒后迟到回复不改变已完成结果。
4. 真正安装V0.6或关闭插件的团员都显示未响应；这两个场景无法远程区分，不得当成确定未安装。
5. 真实团员进出队、离线后重连、实例/普通组同时存在时的活动组映射。
6. 游戏内字号、职业色、长服务器名/未知版本悬浮、40人滚动列表和5秒按钮恢复。

目前只做源码审计、离线多VM模拟和字节核验；没有进行真实多人测试，未宣称通过上述项目。
